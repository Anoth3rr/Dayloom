# 周期事务、长期目标与时间窗口

## 界面与使用方式

原「游戏日程」统一为「周期事务」。分组可选择普通事务或游戏；普通事务默认按本机时间、零点、周一、每月一日开始新周期。现有游戏分组继续使用服务器时区与刷新规则。事务支持每天、指定星期、每周、每月，普通事务也出现在「今天」。游戏专用的体力与材料本文案仅在游戏分组中出现。

新增「重要不紧急」入口。任务可标记为长期事务，设置从哪天开始每天显示；每日推进记录与最终完成分开。勾选今日推进只记录当天，次日重新显示未推进，最终完成后停止每日出现。截止日期可以很远，也可以不设。

任务编辑提供「时间窗口」与「具体安排」。时间窗口的最早、最晚边界各自包含日期和可选时刻，允许仅填写一端。日期未指定时刻时，最早从零点起、最晚到当天结束。可以只保存窗口，不填写精确开始时间和时长；以后可以在窗口内另行安排。既有固定时间任务保持原行为。

周期事务也支持不限时间、固定时刻和每日时间窗口。周/月事务的窗口属于选定的计划日。窗口中的时间按分组时钟解释，游戏以刷新时间划分一天。

## 日历与完成语义

- 无具体安排的时间窗口显示在日历的「全天 / 待安排」区域，覆盖可安排的日期，不伪装成占满整个窗口的固定事件。
- 今天显示已进入可安排日期的任务；超过最晚时间才标记逾期。
- 拖动指定具体时间必须仍满足窗口，不能静默丢掉约束。
- 长期事务的每日推进记录保留在同一任务上，不每天复制任务。
- 周期完成次数仍按周期独立；普通周期与游戏周期共用已有规则引擎。

## 数据兼容

保留版本 1 及原有字段，添加可选字段。`Task.timeWindow` 保存带日期的边界；`Task.longTerm` 保存开始显示日期和已推进日期。原 `gaming` 数据增加分组类别、时钟模式以及活动的不限时间/时间窗口选项，旧游戏数据按原规则读取。前后端共用校验，导入导出与自动备份包含新字段。
