## 项目介绍

Dayloom 将待办清单、日历和周期事务整合在同一个桌面工作区中，适合规划工作任务、学习安排、生活习惯，以及游戏中的日常、周常与材料收集。

任务既可以设置一个截止日期，也可以只确定「最早开始」和「最晚完成」组成的时间窗口。需要长期关注的事项可以标记为「非常重要」，在完成前每天显示在「今天」中。数据默认保存在本机；需要跨设备使用时，可以连接自己的 WebDAV 账号。


## 功能特性

| 功能 | 说明 |
| --- | --- |
| 待办清单 | 按清单管理任务，设置优先级、子任务和备注，可搜索任务名称、备注及清单名称 |
| 截止日期 | 新建时默认使用；设置截止日和可选的截止时刻，无需填写持续时长 |
| 时间窗口 | 设置最早开始、最晚完成，也可进一步安排具体日期、时刻和时长 |
| 非常重要 | 未完成前每天出现在「今天」，即使截止日期还很远 |
| 日历与日程一览 | 查看周历、月历和当天安排，拖动事项即可调整时间 |
| 周期事务 | 支持每天、每周、每月和指定星期，按周期记录完成次数 |
| 多账号同步 | 通过 WebDAV 同步任务、清单、日程、周期事务和完成记录，支持账号切换与离线编辑 |
| 数据备份 | 将当前工作区导出为 JSON，或从备份恢复 |

## 安装指南

面向 **Windows x64**。[GitHub Releases](https://github.com/Anoth3rr/Dayloom/releases) 当前尚未发布可下载的发行包，可以从源码生成可执行文件。

构建环境要求：Windows x64、Git、Node.js 24.x 和 npm。

```bash
git clone https://github.com/Anoth3rr/Dayloom.git
cd Dayloom
npm ci
npm run package
```

生成的便携版位于 `release/Dayloom-<版本号>-Windows.exe`，双击即可运行。构建完成后的应用不依赖用户另外安装 Node.js 或 npm。

## 使用示例

### 截止事项

例如，需要在本周五提交周报：

1. 点击「新建任务」，输入「提交周报」。
2. 保持默认的「截止日期」模式，选择本周五。
3. 如需精确到时刻，将「截止时间」设为 `18:00`；否则留空，表示当天结束前完成。
4. 选择所属清单、优先级，按需添加子任务和备注，然后创建任务。

截止事项会在清单和日历中标注「截止」。设置具体截止时刻后，会按该时刻判断是否逾期。

### 时间窗口

例如，这周需要整理资料，但还没决定具体哪天做：

1. 新建任务「整理资料」，切换到「时间窗口」。
2. 将「最早开始」设为本周一 `09:00`，「最晚完成」设为本周五 `18:00`。
3. 暂时不勾选「设置具体安排」，任务会显示在窗口范围内的待安排区域。
4. 确定执行时间后，再填写具体安排；安排及其持续时长需要落在窗口内。

窗口可以只填一端，边界时刻也可以留空。切换回「截止日期」时，会优先采用窗口中的最晚完成日期与时刻。

### 长期任务

例如，三个月后需要参加考试：创建「准备资格考试」，选择对应的截止日期，将优先级设为「非常重要」。该任务会在完成前每天出现在「今天」，便于持续关注。

完成后，它会退出后续日期的每日关注列表；每一天的展示仍对应同一条任务。

### 周期事务

进入「周期事务」，通过「管理分组」添加分组，再创建事务。选择「普通事务」规划生活与学习安排，或选择「游戏活动」设置服务器时区和刷新规则。

| 使用场景 | 分组类型 | 规则示例 |
| --- | --- | --- |
| 每天阅读 | 普通事务 | 每天完成 1 次 |
| 每周复盘 | 普通事务 | 每周完成 1 次，计划安排在周日 |
| 月度账单整理 | 普通事务 | 每月完成 1 次，计划安排在每月 1 日 |
| 材料收集 | 游戏活动 | 设置材料本开放星期，例如周一、周四、周日 |
| 游戏周常 | 游戏活动 | 按分组的每周刷新日统计本期完成次数 |

游戏的开放星期、服务器时区和刷新时刻需要按实际规则填写，上表仅为配置示例。进入新周期后，会使用新一期的完成进度，历史记录会保留。需要调整某一期的时间时，可在「本期安排」中单独修改。

### 快捷操作

| 操作 | 快捷键或入口 |
| --- | --- |
| 快速添加任务 | 在清单上方输入任务名称，按 `Enter` |
| 新建任务 | `Ctrl + N` |
| 搜索全部任务 | `Ctrl + K` |
| 保存任务编辑 | `Ctrl + Enter` |
| 关闭面板 | `Esc`，未保存的任务编辑会提示确认 |
| 切换主题、调节磨砂效果 | 设置 → 外观 |

截止或到点提醒需要设置日期与时刻，并保持桌面应用运行。

## 跨设备同步

在「设置 → 账号与同步」中添加已有的 WebDAV 账号：

| 字段 | 填写说明 |
| --- | --- |
| WebDAV 地址 | 服务提供的完整 WebDAV 目录地址，例如 `https://dav.example.com/dav/` |
| 用户名 | WebDAV 服务的用户名 |
| 密码 | WebDAV 密码或服务提供的应用密码 |
| 同步目录 | 默认是 `Dayloom`，也可使用独立的目录名称 |
| 账号名称 | 可选，用于区分「个人」「工作」等连接 |

先点击「检查连接」，通过后点击「连接并同步」。服务需要提供目录读写权限，并通过应用对并发写入能力的检查。

要让多台设备共享同一份数据，请在各设备填写相同的 **WebDAV 地址、用户名和同步目录**。首次连接时，如果希望带入当前工作区的任务，可勾选「将当前任务合并到此账号」。

连接后，修改会自动同步，也可以点击「立即同步」。离线修改会先保存到本机，恢复连接后再同步；多台设备同时修改同一任务且发生冲突时，会保留冲突副本供核对。已保存的账号可以切换，各账号拥有独立的本机缓存。

## 数据与备份

桌面数据目录为 `%APPDATA%\Dayloom\`，本地模式的任务主文件为 `data.json`；账号模式使用各自的缓存文件。在「设置 → 数据与备份 → 数据目录」中可以打开实际存储位置。

「导出备份」会导出当前工作区的数据。「导入备份」经确认后会替换当前工作区的记录，恢复前建议先导出一份现有数据。

## 技术栈与项目结构

| 层次 | 技术 |
| --- | --- |
| 桌面应用 | Electron、Node.js |
| 界面与类型 | React、TypeScript |
| 样式与图标 | CSS、Lucide React |
| 数据与同步 | 本地 JSON、WebDAV、三方数据合并 |
| 构建与打包 | Vite、electron-builder |

```text
Dayloom/
├── src/
│   ├── main/                  # 桌面窗口、系统接口与本地存储
│   ├── renderer/              # React 界面及入口
│   │   ├── components/        # 页面与组件
│   │   ├── domain/            # 任务、日程与周期规则
│   │   ├── services/          # 工作区、存储适配与同步状态
│   │   └── styles/            # 界面样式
│   ├── shared/                # 公共类型、数据校验与同步逻辑
│   └── tsconfig.json          # TypeScript 配置
├── config/
│   ├── vite.config.ts         # 前端开发与构建
│   └── electron-builder.json  # 桌面打包
├── assets/
│   ├── icons/                 # 应用图标
│   └── public/                # 静态资源
├── scripts/
│   └── dev.mjs                # 桌面开发启动脚本
├── package.json               # 项目信息、依赖与命令
├── package-lock.json          # 依赖版本锁定
└── README.md
```

开发时使用 `npm run desktop:dev`，同时启动 Vite 与 Electron；`npm run dev` 提供浏览器界面预览。桌面通知和本机文件接口需要在 Electron 中体验。

## 贡献指南

欢迎通过 [Issues](https://github.com/Anoth3rr/Dayloom/issues) 反馈问题或提出功能建议。问题反馈请说明应用版本、Windows 版本、复现步骤、预期结果和实际结果；界面问题可以附上截图。

提交代码修改时：

1. Fork 仓库，从 `main` 创建一个描述修改内容的分支。
2. 安装依赖，使用 `npm run desktop:dev` 开发和检查实际交互。
3. 保持现有的源码分层与 TypeScript 类型约束；涉及用户操作变化时，同步更新 README。
4. 提交前运行 `npm run build`。涉及桌面入口、资源路径或打包配置时，再执行 `npm run package` 并检查生成的应用。
5. 发起 [Pull Request](https://github.com/Anoth3rr/Dayloom/pulls)，说明解决的问题、主要改动和验证结果。一次提交聚焦一个主题，较大的功能调整请先在 Issue 中讨论。

仓库保留应用源码、必要资源与配置，以及项目 README。账号密码、个人任务数据、本机绝对路径、依赖目录、构建产物、测试文件、验证报告和开发计划不应提交；验证步骤和结果可写在 PR 说明中。
